## Proposed ordinary capture and observer boundary

Ordinary releases do **not** inherently depend on the frozen esbuild observer. They use fresh `npm ci` and private Rust build outputs; current ordinary measurement does not invoke `observe-npm.mjs`.

The proposed direction is an ordinary owning-capture adapter feeding the same reviewed composition/projection/renderer core, not another SBOM format or a fabricated `RecipeCompleted`. It must retain the actual installation/build evidence required by **J**. Its concrete provider and lifecycle observation need separate implementation review after the rollout decision.

If that work instead reuses the controlled observer, stop for a separate adaptation decision first. Its esbuild 0.27.3 restriction remains frozen while the actual lock uses 0.28.2. Reviewing native selection, lifecycle commands, output mutation, hardlinks and fallback/download behavior is required; changing a version literal is insufficient. The opt-in collector remains visibly disabled until that decision and review.

## Concrete input scope and exclusions for review

Include contributing Rust source/archives/Git trees, host and target Cargo units, proc macros/build scripts, generated objects and native libraries, Rust sysroot/compiler runtimes, selected compiler/linker/assembler/archiver and relevant helpers/libraries/resources, SDK/header/stub/framework/crt inputs, installed npm build/dev dependencies, native bundler distributions, lifecycle outputs, generated plugin helpers and the actual private bundles. Include logical source-controlled build inputs and the exact command/feature/target/profile context.

Distinguish build material from final runtime contributors. CLI JS that is not retained in its final executable can still be build material; type-only or eliminated modules can still be compiler inputs. Installed/executed material is not excluded merely because linking or minification removes its runtime contribution.

The only proposed exclusions are demonstrably unselected/uninstalled optional packages and uncompiled dev-only Cargo units; operator-owned runtime configuration, secrets and actual installed runtime/store bytes; and separately produced operator assets such as an external Prebid bundle. Represent runtime libraries/imports as logical external requirements. An installed npm Prebid package still remains build material if selected by this build. Unresolved native, tool, SDK, startup, system-library or compiler-runtime contributors are **never** exclusions.

## Public artifact version versus Cargo package version

Keep `SPDXRef-Artifact`, its public asset filename, exact release-tag `versionInfo` from `RELEASE_VERSION`/`github.ref_name`, and SHA-256 of the canonical executable. The source commit remains independently recorded; it is not substituted for the tag version.

Validate the contributing root Cargo component against its verified manifest version, currently workspace `0.1.0`, and retain its Cargo package identity separately. Frozen candidate `root_version()` derives a Cargo version; port that validation without making it the public artifact version selector.

The interim converter also inherits a Cargo purl on the artifact root. The complete-renderer plan must explicitly resolve that mapping: the proposed mapping puts the Cargo purl/version on the separate verified Cargo component and relates it to `SPDXRef-Artifact`, without renaming the public root or changing the tag version. This external-reference adjustment requires approval with the implementation plan; it is not a silent change authorized here.

## Stop point: target-specific rollout decision

No implementation task list is authorized by this feasibility document. The costly **U** cells require a user decision before code:

| Option                                | What proceeds                                                                                                                                                                              | Production consequence                                                                                                                                                         |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Evidence-first waves                  | Plan bounded ordinary Cargo/JS/runtime ownership first; separately design/cost Fastly host-tool closure, GNU/ARM image acquisition, musl runtime materials and Apple SDK/toolchain closure | Keep all seven assets and honest interim inventories; complete generation and the complete seven-row index remain closed until all seven pass                                  |
| Target-specific complete-SBOM rollout | First establish one target's complete closure, then separately approve its production claim while others retain interim inventories                                                        | Requires an explicit amendment to Gate 2's all-seven activation condition. Never drops binaries or silently activates a seven-entry complete index; v2 production stays closed |
| Full-cohort feasibility first         | Pause capture implementation until each target has an approved acquisition/closure method and bounded cost assessment                                                                      | Preserves strict all-seven activation and current release behavior; complete evidence remains deferred without a false completion claim                                        |

The user selected full-cohort assessment first; the options above are not implementation authorization. Even the first option cannot promise a cheap Fastly exception: Fastly tool closure is itself unresolved. Approving either design proposal is not approval of a new qualification resource, controlled selector, schema/policy file, production switch or rehearsal tag.
