# Gate 2: full-cohort closure and cost assessment

**Status:** Docs-only assessment requested on 2026-10-28. No capture implementation, acquisition, image build, qualification, production selection or rehearsal tag is authorized. The strict Gate 2 scope remains in force; the identity-only alternative below is a proposed amendment for a user decision, not an adopted definition of completeness.

**New option for decision:** The user has not approved target-specific activation. The [issue-scoped all-seven build-derived Cargo/npm SBOM option](binary-attestations-phase3-issue-scoped-sbom-option.md) proposes an explicit narrower coverage amendment, with per-SBOM/guide limits and a separate estimate. It is not adopted; strict Gate 2 still governs and Gate 3 Steps 2–5 remain held.

**Scope:** All 21 unresolved cells in the [coverage matrix](binary-attestations-phase3-complete-spdx-implementation.md): seven native, seven platform/tool and seven licence cells. Cargo/JS/runtime capture and complete-generator integration also remain work, but their costs are not hidden inside these U-cell estimates. Part of #1235; draft #1463.

## Basis and limits

Effort means engineering person-days for design, implementation, focused verification and review **if later authorized**. Ranges are judgment estimates, not benchmarks, staffing commitments or elapsed delivery promises. They exclude acquisition/approval waiting, publication/consumer integration and infrastructure purchase or provisioning time. They assume adequate originals can be obtained; missing Apple acquisition or observation capability can invalidate the estimate rather than merely add a known number of days.

The existing workflow allows 90 minutes per build and ten minutes for **Fastly comparison only**. Native jobs have no new comparison allowance. In rehearsal `.16` at `5fa384336`, producer jobs took: Fastly 353s, GNU CLI 494s, Apple ARM CLI 783s, Apple Intel CLI 1,869s, GNU x64 Axum 324s, musl Axum 287s and GNU ARM Axum 288s. Fastly reproduction took 269s and comparison 86s. These [observed results](https://github.com/IABTechLab/trusted-server/pull/1449#issuecomment-6467368408) establish current baseline time, **not capture overhead or complete-closure feasibility**.

No capture experiment or SDK/tool acquisition was run for this assessment. Every strict cell's full 90-minute fit remains unproven. Future feasibility work must measure bounded acquisition, extraction, tracing, hashing, retention and handoff costs in an approved hosted job. Comparison must consume bounded retained evidence; it cannot use its ten-minute budget to reacquire SDKs or discover an unknown tool tree.

## Platform/tool cells: strict versus proposed identity-only amendment

The alternative records selected compilers, linkers, SDKs and images by **exact version, cryptographic digest and authenticated acquisition source**; it explicitly makes no helper/library/file-closure claim. A version label, local image ID or installed-software list alone does not satisfy that alternative.

Including its shared foundation, platform/tool effort is **44–71 days strict**, versus **17.5–30 days for the alternative**. These exclude native/licence providers and do not guarantee that a missing acquisition source becomes available.

GitHub documents weekly standard-image updates and per-run included-software links; it describes Ubuntu/Windows image SBOMs, not an authenticated macOS VM-byte digest. That evidence does not by itself meet either strict closure or a required VM digest. [Hosted runner documentation](https://docs.github.com/en/actions/concepts/runners/github-hosted-runners).

GitHub's current custom-image creation instructions list Linux x64, Linux ARM64 and Windows x64, require separately enabled larger-runner capabilities/permissions, and say provisioning may take hours. This is a possible **new approved resource** for relevant Linux work, not an assumed macOS solution or something to put inside a release's 90-minute budget. [Custom-image documentation](https://docs.github.com/en/actions/how-tos/manage-runners/larger-runners/use-custom-images).

If the alternative's image requirement includes the entire hosted VM, current evidence does not establish the required macOS digest/acquisition route. Do not relabel `ImageVersion` as a digest. Accepting provider provisioning as acquisition, limiting image identity to selected builder containers, or changing Apple builders would each need an explicit scope/resource decision. No such decision is adopted here.

## Combined cost and decision

| Direction                                       | Conditional U-cell engineering subtotal                                        | What remains blocked                                                                                                                                                                         |
| ----------------------------------------------- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Strict all-seven                                | **80–136 person-days** for N/L plus strict platform/tool work                  | Apple acquisition/observation and every measured job-limit/resource check; also Cargo/JS/runtime capture, generator integration and later publication work excluded from subtotal            |
| Proposed platform identity amendment, all seven | **About 54–95 person-days** for unchanged N/L plus identity providers          | Same native/licence originals and possibly Apple acquisition/VM identity; scope no longer claims complete helper/library/file closure. Not adopted                                           |
| Target-specific rollout                         | Cost only the chosen provider wave and its share of foundations, then reassess | Requires an explicit amendment to all-seven production activation and possible assurance-profile changes; no binary is silently removed and no partial seven-row complete index is published |

These subtotals are not delivery bounds: the unresolved external inputs can prevent completion. Initial strict Fastly-only N/L/tool work would be roughly **30–50 person-days**, including shared foundations and excluding Cargo/JS/runtime/generator integration. It is a candidate first wave because some same-build observations already exist, not a proved cheap complete target.

**Recommendation: a target-specific rollout decision**, preserving all seven distributed binaries and honest interim inventories while proving the selected target's complete closure first. This avoids making every target wait for unresolved Apple acquisition and the broadest native/material work. It still needs explicit user approval to amend the current all-seven activation rule; until then strict all-seven remains the governing gate. The identity-only amendment is cheaper but does not by itself resolve the other U cells or establish a complete seven-target path.

No scope amendment, resource, capture code, schema/policy file, production/qualified selector or rehearsal tag follows from this recommendation. Gate 3's v2 implementation steps remain held until the user chooses the Gate 2 rollout/assurance direction.
